# NAVARRO TRADE / Sterling Strategy Session — v5.0 REVIEW

Интерактивная веб-презентация по материалам Navarro Trade и последним исправлениям от 22.10.2026.

## Новое
- Отдельный экран 02: полная оргструктура TO-BE без описаний.
- Экран 03: раскрытие Executive-структуры (CEO → руководство → подразделения).
- Экран бизнес-процессов: 17 этапов международного транзита PetroChina и 6 этапов внутренней оптовой торговли РК; сохранён порядок по сообщению пользователя.
- По нажатию открывается карта процесса: слева этапы, справа текущая операция, соседние этапы, точки взаимодействия с участниками, документы, риски, кейсы и решения.
- Риски КТЖ, вагонов, простоев, невыполнения планов, FX и снижения маржи — в точках операционного соприкосновения.
- Слайд кейсов: удалены кейсы оснащения Dostyk Refinery и импортной партии Jet A-1; кейс по измерениям сформулирован нейтрально через инвентаризацию Navarro в арендованном резервуаре предприятия хранения.
- Стратегический рост: толлинг нефти РК на НПЗ PetroChina, франшизные АЗС ION ENERGY, мобильный ТЗК, иностранные авиакомпании.
- Обновлённые решения сессии.

## Важные ограничения
- Это проект к согласованию, а не приказ/утверждённая оргструктура.
- Фактическая последовательность двух процессов основана на тексте пользователя. Предлагаемые решения и риски отделены от AS-IS.
- Авиационный процесс заправки в крыло подробно не моделируется, поскольку его фактическая последовательность ещё не была дана.
- Отрицательные кейсы намеренно не связывают с именем конкретной нефтебазы: в них говорится «предприятия, ответственные за хранение нефтепродуктов».
- Технические термины ППС, SJS, СТ РК требуют подтверждения ответственными.
- В проект могут входить внутренние сведения. Сайт на GitHub Pages общедоступен.

## Управление
←/→, PageUp/PageDown, Space: навигация по слайдам. F: полный экран. Esc: закрыть процессную схему. В процессной модалке ↑/↓: переход между этапами.

## Размещение
Для безопасного теста публикуйте как `/session-v5/` отдельной папкой, не заменяя `/session/` с правками Codex. После проверки перенести изменения в актуальный `/session/`, предварительно сравнив код и данные.
