# NAVARRO TRADE Overview — версия 2.0

Новая **рабочая** (не утверждённая) веб-версия операционной модели NAVARRO TRADE для обсуждения с коллегами и руководителями группы Sterling. Актуализация по обратной связи 19–20 октября 2026 года.

**Без серверной части, npm, сторонних библиотек и сетевых обращений.** Статический сайт для GitHub Pages; весь контент находится в `assets/data.js`. Исходные фотографии штатного расписания и персональные данные в сборку **не включены**.

## Содержание

- Главная страница с тремя основными сценариями вместо единого универсального маршрута.
- Интерактивная организационная схема: прямое подчинение ИТ-PM гендиректору, заместитель курирует коммерцию и логистику; две ветки финансовой дирекции; функциональная связь логистики с авиационным отделом.
- Три интерактивных сценария с 9, 9 и 11 этапами: оптовая реализация авиакеросина, заправка непосредственно в крыло, международный транзит.
- Ветвления оплаты: предоплата, частичная оплата, отсрочка. Заказчик инициирует базис, договор закрепляет итоговый.
- Карта рабочих взаимодействий с JetWayLogistics, Dostyq Refinery, авиационным терминалом, Sterling Energy и Ion Energy; границы ответственности операторов.
- 17 функциональных профилей подразделений / управленческих позиций; 19 подробных должностных профилей.
- Предварительная RACI-матрица, справочник 12 типов документов, 10 железнодорожных статусов, 6 отклонений, 10 вопросов для утверждения.
- Поиск и мобильная навигация, работающие ссылки для передачи коллегам.

## Обновление существующего репозитория

Исходный репозиторий: `git@github.com:armashkiss/NavarroTradeOverview.git`.

1. **Сохраните копию / текущий коммит** перед заменой файлов.
2. Распакуйте файлы из ZIP в корень существующей папки Git-репозитория. Не создавайте дополнительную вложенную папку; `index.html` должен оставаться в корне.
3. `git diff`, `git status` — проверьте изменения. Новая версия заменяет `index.html`, `assets/app.js`, `assets/style.css`; добавляет `assets/data.js`.
4. Старая генерация `site-data.js` через Obsidian больше **не является источником для v2**. Старые `site-data.js` и `scripts/build_site.py` желательно удалить из публичной ветки после резервного копирования, чтобы устаревший контент не оставался доступным по прямым ссылкам. Не удаляйте свои файлы `.codex/private` и исходный Vault без отдельного решения.
5. После проверки выполните `git add -A`, `git commit -m "NAVARRO TRADE: operating model v2"`, `git push origin main`.
6. В GitHub: Settings → Pages → Deploy from a branch → main / root. При существующей настройке изменений не требуется.

Для безопасной совместной работы можно сначала создать новую ветку `v2-review` и сделать pull request, не публикуя без утверждения.

## Поддержка актуальности

Главный источник данных веб-сайта **`assets/data.js`**. Его массивы `departments`, `staff`, `roles`, `companies`, `processes`, `raci`, `docs`, `statuses`, `questions` связаны с интерфейсом в `assets/app.js`. После изменения данных сайт обновляется автоматически при перезагрузке страницы.

Оригинальный Obsidian Vault версии 1.0 **не обновляется автоматически** при изменении этой веб-сборки. Перед дальнейшей синхронизацией следует переработать исходные Canvas и Markdown, иначе старые названия («отдел логистики и перевалки», «техническая служба») могут вернуться. Смотрите `docs/CHANGELOG_FROM_V1.md`.

## Проверка перед публикацией

- Не включать фамилии, исходные кадровые фото, договорные цены, конкретные тарифы, коммерческую тайну и доступы.
- Уточнить юридические названия предприятий и реальные полномочия подписантов.
- Проектные отделы с нулём отдельных ставок не выдавать за укомплектованные подразделения.
- Убедиться, что руководство разрешило публично раскрывать саму операционную модель. GitHub Pages не является закрытым корпоративным порталом.

## Технические требования

Все современные браузеры с поддержкой JavaScript и SVG; никаких cookie, трекеров, аналитики и внешних API. Проверено в headless Chromium для desktop 1440×900 и mobile 390×844; 11 основных маршрутов, клики по схемам, поиск и переключение сценариев.
